## I build software around real workflows

I'm a Computer Engineering graduate from Portugal. I enjoy problems where there is an existing manual, repetitive or messy workflow and software can make it substantially better.

That usually means understanding the process first, then building the product around it: customer-facing applications, admin systems, browser integrations, relational data, automation and the less-visible engineering needed to make those systems reliable.

## How I work

- **Start with the workflow.** I try to understand the user, constraints and failure cases before deciding what the interface or architecture should look like.
- **Automate safely.** For actions that can publish, send or change business data, I prefer reviewable human-in-the-loop flows over invisible automation.
- **Treat data as part of the product.** I work with relational schemas, PostgreSQL/Supabase, RLS policies, RPCs and permission boundaries rather than treating the database as an afterthought.
- **Validate the running product.** I use type/build checks, automated tests and browser-level validation where the workflow depends on real UI behaviour.
- **Use AI as an engineering multiplier.** I use AI tools for planning, implementation, review and debugging, but still inspect changes and validate the result against the repository and running application.
